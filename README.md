# OKX Early Momentum Scalp Bot

Production-ready бот автоторговли на **OKX USDT-SWAP** по стратегии
**Early Momentum Scalp Long** с фильтром толпы (Long/Short Account Ratio).

Идея: входить в LONG на альт-SWAP, где импульс только начинается —
Supertrend развернулся вверх, RSI не перегрет, OI растёт вместе с ценой,
цена на небольшом откате, а толпа в лонгах ещё не перегрета. Быстрый
скальп с TP1/трейлингом/таймаутом, а не удержание позиции.

Деплой на сервер (Docker или systemd) — см. [DEPLOY.md](DEPLOY.md).

> ⚠️ **ВАЖНО**: автоторговля **убыточна без контроля**. Ни одна
> стратегия не гарантирует прибыль. Всегда начинайте с paper-режима,
> используйте демо-счёт OKX (`OKX_SIMULATED=true`), контролируйте
> дневные лимиты убытка и никогда не рискуйте суммой, которую не готовы
> потерять.
>
> Этот бот торгует **только обычные бессрочные фьючерсы (USDT-SWAP)**.
> **Event-контракты OKX "Up/Down 5m" (5-минутные бинарные event
> contracts) НЕ используются и НЕ поддерживаются этим ботом** —
> это принципиально другой инструмент с иной механикой пейаута и
> экспирацией, здесь не применяется вообще нигде в коде.

## Стратегия

**Эталонный сетап**: GRVT-USDT-SWAP long ~0.277 → 0.282 (~+1.9% цены),
20x isolated, ~14 минут удержания, сильный % к марже. Бот ищет похожие
условия: ранний импульс, а не хайп на хаях.

### Скрининг (каждые `SCAN_INTERVAL_SEC`, по умолчанию 90с)

Hard filters (жёсткий отсев вселенной USDT-SWAP альтов):

- инструмент `live`, торгуется в паре `*-USDT-SWAP`, не стейблкоин
- 24ч изменение цены в диапазоне `+3% … +18%`
- открытый интерес ≥ `MIN_OI_USD`
- 24ч оборот в USDT ≥ `MIN_24H_QUOTE_VOLUME_USDT`
- `|funding rate|` не экстремальный
- максимальное плечо инструмента ≥ `MIN_MAX_LEVER`
- спред `(ask-bid)/mid` ≤ `MAX_SPREAD_PCT`

Скоринг 0–10 (см. [`src/strategy/scorer.js`](src/strategy/scorer.js)):
Supertrend 15m/1H, RSI14 15m/1H, MACD-гистограмма, динамика OI, откат
от 24ч хая (не "догонять" памп), фильтр перегрева толпы (Long/Short
Account Ratio), funding. Вход рассматривается только при
`score >= MIN_ENTRY_SCORE` (по умолчанию 7.5) и отсутствии открытой
позиции по инструменту.

### Фильтр толпы (Long/Short Account Ratio)

`longPct = ratio / (1 + ratio) * 100`. Хранится история 5-минутных
баров на инструмент. **Crowding spike** — перегрев толпы в лонгах —
срабатывает если:

- `longPct >= LS_CROWDING_LONG_PCT` (по умолчанию 78%), **или**
- `longPct` вырос на `>= LS_CROWDING_DELTA_PP` п.п. за последние 2–3
  бара (10–15 минут)

При spike вход в LONG по умолчанию **пропускается** ("ловушка толпы").
Умеренный `longPct` (45–68%) вместе с ростом OI, наоборот, добавляет
очков как подтверждение здорового раннего импульса.

### Вход и управление сделкой

- Лимитный ордер в зоне входа (около лучшего бида); если цена уже
  ушла от сигнальной больше чем на `MAX_ENTRY_CHASE_PCT` (0.4%) —
  вход отменяется, догонять цену бот не будет.
- Размер позиции считается от `RISK_USD_PER_TRADE` (маржа сделки) и
  выбранного плеча (`DEFAULT_LEVERAGE`, либо `MAX_LEVERAGE` при
  `score >= HIGH_LEVERAGE_MIN_SCORE`), режим маржи — `isolated`.
- Сразу после входа: **TP1** (`TP1_PCT`, закрывает `TP1_CLOSE_RATIO`
  объёма) + **SL** (под структурой Supertrend 15m / swing low, в
  диапазоне `1.5–3.0%` от входа) как OCO-алгоордер на бирже.
- После TP1: SL переносится в безубыток, остаток ведётся трейлингом
  (`TRAIL_PCT`) либо закрывается при развороте Supertrend 15m вниз.
- Таймаут: если за `TRADE_TIMEOUT_MIN` минут нет TP и импульс угас
  (RSI падает и/или Supertrend грозит развернуться) — закрытие по
  рынку.

### Защиты

- `AUTO_TRADE=false` (по умолчанию) — бот **не отправляет ордера на
  биржу**, только сканирует, считает сигналы, ведёт полную
  paper-симуляцию сделок (виртуальные позиции с реальным управлением
  TP/SL/трейлингом по реальным ценам) и шлёт всё в Telegram.
- `DRY_RUN=true` (по умолчанию) — доп. предохранитель: даже при
  `AUTO_TRADE=true` ордера не отправляются на биржу, только логируются.
- Kill switch: файл `STOP` в корне проекта или команда `/stop` в
  Telegram — мгновенно запрещает новые входы.
- Дневной лимит убытка (`DAILY_LOSS_LIMIT_USD` / `_PCT`) → halt до
  следующего дня.
- Лимит сделок в день (`MAX_TRADES_PER_DAY`).
- Cooldown (`COOLDOWN_MINUTES`) после `COOLDOWN_AFTER_LOSSES` подряд
  убыточных сделок.
- Не усредняется в минус, не открывает новую позицию по инструменту,
  где уже есть открытая.
- Останов при серии ошибок API OKX (`API_ERROR_STREAK_HALT`).
- Идемпотентность входа через `clOrdId` (без дублей при повторных
  циклах).
- Каждый ордер и событие сделки логируются в `logs/YYYY-MM-DD.log`.

## Архитектура

```
src/
  config.js                 загрузка и валидация .env
  okx/
    client.js                подпись запросов (HMAC), retry на 429
    market.js                instruments/tickers/candles/funding/OI/rubik
    trade.js                 balance/positions/order/order-algo/close
  indicators/
    rsi.js, macd.js, supertrend.js   чистые функции (юнит-тестируемые)
  strategy/
    lsRatio.js                longPct/shortPct + crowding spike
    scorer.js                 скоринг кандидата 0..10
    scanner.js                отбор вселенной + обогащение + скоринг
  execution/
    risk.js                   sizing, guard-проверки, плечо
    trader.js                 вход, TP1/SL/трейлинг/таймаут, закрытие
  state/
    store.js                  персистентный JSON-стейт (позиции, дневная
                               статистика, cooldown, kill switch)
  notify/
    telegram.js                уведомления + команды бота
  index.js                    главный цикл: scan -> score -> enter -> manage
test/                         юнит-тесты (node:test)
.env.example                  шаблон конфигурации
```

Главный цикл: сканирование вселенной каждые `SCAN_INTERVAL_SEC`,
управление открытыми позициями каждые `MANAGE_INTERVAL_SEC` (TP/SL
проверяются по реальной цене чаще, чем идёт полный ресканг рынка).

## Установка

Требуется Node.js ≥ 18.

```bash
npm install
cp .env.example .env
```

Заполните `.env`:

- `OKX_API_KEY`, `OKX_SECRET_KEY`, `OKX_PASSPHRASE` — ключ API с
  правами **Read + Trade** (Withdraw НЕ включать). Создаётся на
  www.okx.com → API Management. Для демо-счёта используйте отдельный
  ключ, созданный в режиме Demo Trading, и `OKX_SIMULATED=true`.
- `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
- `TELEGRAM_CHAT_ID` — узнать у [@userinfobot](https://t.me/userinfobot).

Без API-ключей бот всё равно запускается и работает в режиме
скрининга/paper (публичные эндпоинты OKX не требуют авторизации), но
не сможет узнать баланс аккаунта — портфельный риск в этом случае не
проверяется.

## Запуск: paper / signals-only (по умолчанию)

```bash
AUTO_TRADE=false npm start
```

Или просто оставьте `AUTO_TRADE=false` в `.env` и запустите:

```bash
npm start
```

Бот будет сканировать рынок, считать score, слать сигналы в Telegram
и вести **полноценную paper-симуляцию** сделок (виртуальные позиции с
реальным TP1/SL/трейлингом/таймаутом по живым ценам), не отправляя ни
одного реального ордера на биржу. Рекомендуется прогнать бота в этом
режиме и накопить статистику не менее нескольких десятков сигналов,
прежде чем включать live.

## Запуск: LIVE

1. Установите `AUTO_TRADE=true` и `DRY_RUN=false` в `.env`.
2. Начните с `OKX_SIMULATED=true` (демо-счёт OKX) — это позволяет
   проверить весь цикл размещения реальных ордеров без риска денег.
3. Только затем `OKX_SIMULATED=false` с боевыми ключами, начиная с
   минимального `RISK_USD_PER_TRADE`.

```bash
npm start
```

Немедленный останов новых входов в любой момент:

```bash
touch STOP
```

или командой `/stop` в Telegram. По умолчанию (`CLOSE_ON_STOP=false`
в поведении бота) открытые позиции при `/stop` не закрываются
автоматически — управляйте ими вручную или дождитесь срабатывания
TP/SL.

## Telegram-команды

| Команда | Действие |
|---|---|
| `/status` | режим, equity, открытые позиции, дневная статистика, halt/cooldown/STOP |
| `/positions` | список открытых позиций |
| `/stop` | запретить новые входы (kill switch) |
| `/start` | снять kill switch |
| `/mode paper\|live` | пометка режима в статусе (реальная торговля всё равно требует `AUTO_TRADE=true` в `.env`) |
| `/set risk 5` | переопределить риск на сделку (USDT маржи) без перезапуска |

## Ограничения и известные допущения

- История OI (`getOpenInterestHistory`) берётся из агрегированного по
  базовой валюте эндпоинта `rubik/stat/contracts/open-interest-volume`
  — это прокси для тренда OI конкретного SWAP-инструмента, а не точный
  OI по контракту (используется только как дополнительный балл в
  скоринге, не как hard filter).
- Rubik-эндпоинты OKX (long/short ratio, OI history) имеют более
  строгие лимиты запросов, чем обычные market data — при сканировании
  большой вселенной клиент автоматически делает retry с backoff на
  HTTP 429.
- WebSocket не используется — весь опрос идёт через REST на
  `SCAN_INTERVAL_SEC`/`MANAGE_INTERVAL_SEC`; для более быстрой реакции
  на TP/SL можно уменьшить `MANAGE_INTERVAL_SEC`.
- Short-режим (`ENABLE_CROWDING_SHORT_FADE`) отключён по умолчанию и
  является экспериментальным — в v1 бот торгует только LONG.
